# Clipper — workspace rules

- **Commit policy:** after every major change, feature implementation, and bug fix, run the `/git-acp` slash command (git add + commit + push) and make the commit message state what was changed. Do not accumulate unrelated work into one commit.
- **Secrets:** real keys live only in the root `.env` (gitignored). Never commit, print, or hardcode `.env` contents, `cookies.txt`, or the Upload-Post JWT. If a new file contains secrets, gitignore it BEFORE any commit. Postiz container secrets (JWT, provider OAuth apps, admin credentials) live in gitignored `postiz/.env` + `postiz/.admin-credentials`; only the non-secret `POSTIZ_API_KEY` sits in the root `.env`.
- **Repo layout:** the OpenShorts engine (upstream: github.com/mutonby/openshorts, MIT) is absorbed in `openshorts/` — local patches to `main.py` / `app.py` / `docker-compose.yml` / `gemini_worker.py` are intentional, documented in README.md "Built on OpenShorts", and get overwritten only on purpose. Tooling lives in `scripts/*.ps1` + `*.bat` wrappers.
- **Docs stay truthful:** PLAN.md's verification log is the source of truth for what is proven; update it (and README.md) as part of any change that alters pipeline behavior.
- **Verification discipline:** every pipeline change is verified against a real run before being declared done; record the run in PLAN.md's verification log.
- **Posting safety:** all posting legs must stay dry-run by default; real posts need explicit `--post` + a specific `--clip` (uploader.bat) or `-Post` + a specific `-ClipIndex` (post-clip.ps1 AND postiz-post.ps1); `schedule-skill-edit.ps1` needs `-Post` (batch schedule of `posts/skill-edit/` manifest, Postiz-only). Primary leg: `uploader.bat` — self-hosted, no vendor cap, **adapters** for YouTube (official Data API), Instagram + Facebook (official Graph API), TikTok (Content Posting API) and Bilibili (bilibili-api-python); its credentials live only in the root `.env` + gitignored `uploader/credentials/`. **Honest scope: only YouTube and Bilibili have ever completed a real post — Instagram, Facebook and TikTok have never been given credentials, so never describe the system as "posting to 5 platforms live".** Scheduler leg: `postiz-post.ps1` via local Postiz (`postiz.bat start`; YT/IG/FB/TikTok — no Bilibili, and it only fires while Docker Desktop is running). Fallback: `post-clip.ps1` via Upload-Post (YT + IG, 10/month free tier). Keep the 2/day cadence — no vendor cap does not mean batch-dumping.
- **Numbers in docs must be measured, dated and sourced:** any view/subscriber/engagement figure states the tool it came from (YouTube Data API v3 / ledger.json / oEmbed), the query date, and what is excluded. Never carry a number forward without re-querying, never imply a leg or a platform is live because its code exists, and never count deleted-or-moved videos, the wrong-channel duplicates on `UCukwNg3W2iujMume3-3YpcA`, pre-project videos, or unverifiable Bilibili figures as project results.
- **No personal identifiers in tracked files:** this repo is public. Google account addresses, phone-linked account names and similar PII stay in the gitignored `.env` / local notes, never in README.md, PLAN.md or READY_TO_POST.md.
